### 值得复用的判定

- **`--strict` 会拦 Markdown 加粗，别去改校验器**。写immich 时被拦下，
  拦得对——页面不解析 Markdown。历史 29 条有同样问题，属存量债，新条目不要继承。
- **上游不在白名单域名时，填官方镜像 + 正文说明**。Kdenlive 上游在
  `invent.kde.org`（KDE 自建 GitLab），`links.github` 填 `github.com/KDE/kdenlive`
  并写明「GitHub 是镜像」，否则读者会去错仓库提 issue。
- **版本号取自真正提供二进制的那个地方**。Kdenlive 的 GitHub 无 release 资产
  （走 KDE 发布流程），版本从 `download.kde.org` 目录名读。
- **自托管方案的平台只填服务端平台**。Immich 是 Docker 服务端，填
  windows/macos 会让人以为有桌面版。
- **`alternatives` 宁可留空**。硬塞「看起来相关」的工具（给 lossless-cut 塞
  yt-dlp、给 kdenlive 塞 blender）比留空更糟，会主动误导。留空会让审计缺口
  数字上升，那是准确反映不是退步。
- **release 资产名里可能直接写着别用这个**。LosslessCut 的
  `..._DONT-USE-THIS-FILE.pkg`、Windows ARM64 的 `.appx` 都是。
