## 第二轮优化：补齐 99 条许可证（GitHub 机器核验）

- 思路：缺口 137 条不能靠猜，但 GitHub 的 licensee 能给出可核验的 SPDX 标识。三轮探针：
  `repos/{o}/{r}` → 81 条；根目录许可文件名判双许可（LICENSE-MIT + LICENSE-APACHE）→ bevy/egui/ruffle/o3de 记 `MIT OR Apache-2.0`；
  licensee 认不出的读 LICENSE 正文，只认 `SPDX-License-Identifier` 行或正式许可名称 → 15 条。
- 故意留空：docker-android（Apache-2.0 + 附加条款的自定义许可，记成 Apache-2.0 会抹掉限制）。
- 新增 `npm run license:audit`（scripts/license-audit.mjs，只报告不写数据，依赖已登录的 `gh`）。
  不自动写入的原因写在脚本头：按行号插字段会把 guide 代码块里 4 空格缩进的示例代码当成字段 ——
  这轮就误插了 playwright / plasmic 各一行，已还原；改用「插入后 item.license 是否生效」反查。
- `lib/license-info.ts` 补 `EUPL-1.2`。
- 缺口 137 → 38；剩余 38 条全是「仓库没有机器可识别的许可文件」，需人工读原文。
  其中可能有 BSL / fair-code（源码可见但非 OSI），若确认要按 n8n 先例改 source。

## 第三轮优化：剩下 38 条许可证收口（缺口 38 → 0）

- 关键判断：这 38 条不是同一类问题，分三档处理，别一律当「缺字段」：
  A 24 条真实开源/CC → 填 license；B 3 条 BSL-1.1（surrealdb/spacetimedb/emqx）→ license + kind app；
  C 11 条自定义/EULA/无许可文件 → 不填 license，kind 改 app，正文承担（n8n 先例）。
- 新增映射：CC-BY-SA-3.0、MIT-CMU、ImageMagick、BSL-1.1；`tier` 加第四档 `source-available`。

- 新增断言：kind=app 且无 license 的条目，正文必须提许可（LicenseNote 不显示许可行时的唯一出处）。

- 端点：`POST /api/mcp`，MCP Streamable HTTP 最小子集（只 POST、回 application/json、不做 SSE，GET 返 405）。
  协议版本 2025-06-18；客户端报老版本时回自己的版本。

- 三层拆分：`lib/mcp-protocol.ts`（纯函数，可单测）→ `lib/mcp-tools.ts`（server-only，读目录）→
  `app/api/mcp/route.ts`（限流 60/min/IP、CORS `*`、站点地址回退到 request origin）。
