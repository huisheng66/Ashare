## 修复后台条目页打不开（419379393）

- 现象：`/admin/items/*` 整页渲染失败。根因是 React 拒绝把**函数当 prop** 传给客户端组件（`Functions cannot be passed directly to Client Components`）。
- **根因不在代码，在验证方法**：上一轮那个「服务端渲染好表单、把 renderRollback 函数当 prop 传给客户端组件」的绕法，**tsc / eslint / next build 全都通过**，我据此宣布完成 —— 但那些检查抓不到不可序列化的 prop，只有真实渲染才暴露。
- 改法：客户端组件自己 import server action（`FeedbackForm` / `SubmitForm` 本来就这么做，本项目已有先例，我早该照抄）。
- **可用的验证手段（本机）**：
  - 浏览器工具（agent-browser / chrome headless / playwright）在这台机器上都跑不起来 —— spawn 受限或超时，npm 装包也 502。**别再指望浏览器。**
  - 可行办法：`createSessionToken(secret, {username, role})` 直接生成合法会话 cookie，用 curl `-H "Cookie: ashare_admin=<token>"` 请求受保护页面。绕开「server action 需要浏览器执行 JS 才能登录」。
  - 造数据/清理都**直接写 SQL**，别走 `saveItem` —— 它会再记一条历史/递增 row_version，清理不干净。
- **沉淀的判断**：跨服务端/客户端边界时，构建通过不代表渲染能过。凡是「把服务端的东西传给客户端组件」的设计，必须实际请求一次页面并看日志。
- 验证：造 2 版历史 → 带 cookie 请求 → HTML 里有 v1/v2、「当前」、「回滚到这一版」，dev 日志该错误计数 0。收尾用 SQL 复原，`seed:drift` 报 0 条不一致。
