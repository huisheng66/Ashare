### Turnstile 集成收尾：三个必须记住的坑

1. **CSP 拦 iframe（最大坑）**：Turnstile 窗口是 challenges.cloudflare.com 的 iframe。
   proxy.ts 的 `default-src 'self'` 未声明 frame-src 时把它一起拦掉 → 控件渲染空白，
   Cloudflare 报 300030，浏览器报的是**本站自己的 CSP 违规**（容易误判为 Cloudflare 问题）。
   已放行 script-src / connect-src / frame-src；不做 env 条件放行——中间件在 Edge 运行时，
   env 是构建期内联的，条件放行会静默失效。
2. **控件自己注入同名隐藏字段**：表单内渲染时 Turnstile 会插入 `cf-turnstile-response`，
   官方 Next.js 参考实现直接读它。我再加一个同名字段 → 服务端拿到哪个取决于 DOM 顺序。
   已删掉自己那个。
3. **「令牌单次有效」在这套凭据上不可靠**：同一令牌直连（绕代理）、加 remoteip /
   idempotency_key 变体、间隔数分钟，siteverify 连回 5 次 success；官方测试密钥 3x…
   却正常返回 timeout-or-duplicate。已加进程内核销表（SlidingWindowLimiter limit=1、
   300 秒窗口、键存 SHA-256）兜底。

### 端到端验证方法（可复用）

- **headless Chrome 会被 Cloudflare 挡**（无 iframe、无令牌、报"Widget seem to have hung"）；
  必须用**有头** Chromium。用 agent-browser 自带内核
  `%LOCALAPPDATA%\ms-playwright\chromium-1234\chrome-win64\chrome.exe` + Node 22 内置
  WebSocket 直连 CDP（无需装 playwright 依赖），比 agent-browser CLI 稳（其 daemon 的
  eval/screenshot 上下文会漂移，出现过 about:blank 与 inputs 计数抖动）。
- 重放测试要**确定性注入**：控件会在异步挑战完成时把新令牌写回字段，直接改值再点提交会
  被覆盖。做法是移除控件注入的字段、换成自己只含旧令牌的字段，再 requestSubmit。
- dev server 的内存限流（公开写 3 次/10 分钟）会污染验证：跑之前重启 dev server 清配额。
  另外运行中的 dev server 不会加载后加进 .env.local 的 Turnstile 变量，必须重启。
- 三阶段结果（全绿）：siteverify 直连 success/hostname=localhost/action=contact → 真实表单提交成功 →
  同一令牌重放被拒「人机验证未通过」。验证中我把 dev server 重启过几次，最后一次留在后台运行。
