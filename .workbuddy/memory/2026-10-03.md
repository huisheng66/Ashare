### 关键设计判断（改动前必读）
- **防盗链方向不能反**：站内图片有限可防，爬虫与分享流量不可枚举。无 Referer 必须放行（地址栏直开/微信内置浏览器/爬虫抓 og:image），否则等于把索引和分享一起废掉。
- **拒绝响应必须 `no-store`**：图片路由本是 `immutable` 一年缓存，403 若带上会被缓存住，改配置后仍不放行。
- **CORP 是第二道防线**：Referer 会被浏览器策略裁剪，`same-origin` 在浏览器侧兜底。
- **统计不存 IP**：否则 clicks.jsonl 变成第二份用户数据。
- **语义层只管跨字段一致性**：单字段必填归各入口校验，否则同一问题在两处不同措辞报错（这正是本轮唯一回归的成因）。

**踩坑：仓库文件是 CRLF**
- 补种子的脚本连续三次静默什么都没做。根因：`$` 前留着 `\r`，`slug: "x",$` 永不匹配。另一个坑：shell 会把 `node -e` 里正则的 `$` 吞成字面量。
- 解法：写脚本文件而非 `node -e`；按条目切片而非逐行判重；读入时 `.replace(/\r\n/g,'\n')`、写回时恢复原行尾（否则 diff 变全文件）。
- 写文档时也别用 shell 里的反引号（会被当命令替换），用 Edit 工具。

**语义规则抓到真实数据错误**：yt-dlp 标 `opensource` + `script` 组合不合法（矩阵里 `opensource` 只配 `opensource`/`app`）。它是 Unlicense 开源项目，「脚本」只是形态描述，`kind` 已改为 `opensource`（运行库 + 种子）。

**shell 转义教训（很实用）**：`node -e "..."` 里的正则 `$`、`\\` 极易被 shell 吞掉。凡是要批量改数据文件，一律写 `.mjs` 脚本再 `node` 执行。
