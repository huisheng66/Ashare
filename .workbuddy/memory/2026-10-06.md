### AST 断言自身的两个 bug（值得记）

写断言工具时踩的坑，两个都会造成**假通过**：

1. **围栏必须配对计数**。用 `/^```(\S*)/gm`扫会把每个代码块的**收尾**围栏也算进去，
   于是每个代码块都误报「缺语言标签」。正确做法是 `fenceLines[i]` 与 `fenceLines[i+1]` 配对。
2. **只扫 `paragraph` 会漏链接**。列表和表格里的链接全在 blind spot 里——
   实测只扫 paragraph 时anydoc 只看到 4 个链接，补上 list/table 后是 19 个。
   `list.items` 是 `Node[][]`（要 `.flat()`），`table.head` 是 `Node[][]`、`table.rows` 是 `Node[][][]`（要 `.flat()` 与 `.flat(2)`）。
   **字段名猜错= 断言在检查空气，而且不报错。** 先 dump 一个真实节点看结构再写。

### 顺带修掉的两个真实缺陷

**1. `lib/license-info.ts` 缺 `CC-BY-4.0`**

free-programming-books 用 CC BY 4.0，是合法 SPDX 标识，不写进 TABLE 里前台就静默不显示，
读者会以为没核过。已补为 `permissive` + 「允许商用闭源分发，需署名」
（CC-BY 只要求署名，不要求衍生作品同许可，与 CC-BY-SA 不同）。

**2. `SYNCED_FIELDS` 漏了 `license` 与 `kind`**

这正是上一轮新加的那条测试要防的「漂移能查出来的字段必须能同步修」——
但我当初把 `license` / `kind` 列进了 `intentionallyManual` 豁免清单，判断是错的：

- `license` 是项目自身的客观属性，后台无从手工裁定，不存在合法偏离
- `kind` **必须**能在种子里显式覆盖推导值，否则修正传不到运行库

实际后果：给 n8n 加了 `kind: "app"` 后，跑 `seed:sync` 说「运行库已是最新」，
但运行库的 kind 仍是`opensource`。已把两者移入 `SYNCED_FIELDS`，
豁免清单收缩到只剩 `price`（商业谈判结果，后台可维护）。

**教训**：豁免清单本身需要理由充分。「先排除掉，以后再说」会在第一次真正需要同步时变成静默失效。

### 连带发现并修正的数据错误

`n8n` 的 `source: "opensource"` + 无显式 kind → `seedToItem()` 推成`kind: "opensource"`

## 镜像校验机制（用户要求「加 256 验证」）

用户拍板：网盘分发本身不可信（可被替换、撤回、投毒），
唯一让人确认拿到的是不是正确文件的办法是**把校验值一并给出**。
按用户选择「先把校验机制做好」执行。

### 上游校验文件实测（决定字段设计）

| 项目 | 上游提供什么 | 结论 |
| --- | --- | --- |
| freecad | 标准 SHA-256（`-SHA256.txt`） | 唯一可用的 |
| texstudio | 只有 SHA1（`hashes.txt`，40位） | 已弃用，不采纳 |
| dbeaver | 无| 填不了 |
| kicad / blender / libreoffice | 无 | 填不了 |

选SHA-256 而非 SHA1/MD5：Windows 10+ 自带 certutil、macOS/Linux 自带 shasum，
读者不需要额外装任何工具就能验。

### 关键设计：哈希必须绑定具体文件

`ItemLinks` 新增 `diskSha256`（64位十六进制）+ `diskFile`（含版本号的文件名），
**强制成对出现**。理由：磁盘槽位填的是 `LatestRelease/` 这类**随上游发版浮动的目录**，
哈希只在某个具体版本上成立。只写哈希不写文件 → 读者不知该比对哪个包；
只写文件不给哈希 → 读者以为有校验而跳过核对，**比明确写「未提供校验」危险得多**。

`mirrorChecksum()` 缺任一项即返回 undefined，前台宁可不显示也不显示残缺校验。
后台同步硬校验：格式必须 64 位、两者必须同时存在。

### 渲染（components/OutboundLink.tsx）

新增 `MirrorChecksumNote`，与 `MirrorNote` 分开：
说明是**读**的，校验是**照着跑**的 —— 所以哈希必须可复制、命令必须能直接粘贴。
哈希按 4 位分组便于人工逐位核对（`formatSha256`）；
命令固定 `certutil -hashfile "<文件>" SHA256`（Windows 通用）。

`ItemLinks` 里校验信息**跟着镜像走**：没有镜像链接却写校验值 =挂了个无从核对的文件。

### 测试

`tests/seed.test.mjs` 新增 3 项：
- 校验值格式与成对绑定（含解析函数与原始字段一致性）
- **半截校验信息不得渲染**（反面承诺，5 种残缺/非法组合）
- 哈希分组只影响展示、不影响比对值

验证有效性时把哈希改成 63 位（仍能过类型检查与长度上限，唯一破绽只有校验规则本身），
测试报 `freecad:SHA-256 必须是 64 位十六进制，实际长度 63`。

**关键实测发现**：TeXstudio 的 `hashes.txt` 同时给了 SHA1 和 SHA-256两行，
我本地算的 SHA-256 与上游那一行完全吻合 —— 这坐实了镜像站忠实同步上游。
DBeaver 的低一档可信度**必须在 diskNote 里讲明**，笼统写「已核验」是不诚实的。

### 网盘链接 vs 镜像站链接，性质完全不同

- 镜像站 `LatestRelease/`：随上游发版**自动更新，永不过期**，但点进去要找文件
- 网盘分享：**固定版本快照，不会自动更新**，但点开即可下载、有哈希可核

所以三条 diskNote 都写了「网盘里是固定版本的快照，上游发新版不会自动更新」，
避免读者以为网盘里永远是最新版。`disk` 槽位最终改为指向网盘链接。

## 详情页铺满（用户：「能不能把这个页面铺满，但是用户的观感是第一位的」）

### 根因定位

`shell` 限死 1200px（`max-width: 75rem`），详情页在其内又分`1fr + 340px`，
主栏拿到约 750px 但内容用 `max-w-[40em]`（约 640px）再收一道 —— 右侧双重空白。

**`shell` 被页头、页脚、首页卡片网格共用，不能全局加宽**：
首页 4 列卡片会变成每张 370px、页脚 4 栏过宽，这些地方本来不需要更多信息。

### 方案：新增 `shell-wide`（1440px）+ 正文分栏

`app/globals.css` 新增 `@utility shell-wide`（`max-width: 90rem`），仅详情页使用。
实测：详情页容器 1422px，页头仍是 1200px，首页完全未受影响。

### 关键判断：不能简单铺满

中文正文约 40 汉字（20em）是舒适上限，超 50 字眼睛回扫易串行。
简单去掉 `max-w` 会让一行超 60 汉字 —— **观感反而变差**。
正确做法是让空间被**分栏填满**，每栏仍保持舒适行宽。

### 踩坑一：`columns-2` 的自动平衡对长短悬殊的段落无解

初版用 `xl:columns-2`，FreeCAD 三段是 73/147/69 字，自动平衡排出
「左 1 段、右 2 段」，**两栏高度差 63%**，右边一栏孤零零拖到底。

**CSS columns 没法表达「这一栏该放哪些段」，只能交给浏览器猜。**

### 踩坑二：贪心分配照样摆反

改成「装得下就装」的贪心后，73+147 一起塞左栏、69 在右栏 —— 更不均（78%）。
贪心只看**当前栏有没有过半**，不比较「放进去」和「换栏」哪个更均衡。

### 最终方案：穷举切分点 + 不均衡就退回单栏

新增 `lib/bodyColumns.ts` 的 `splitBodyColumns()`：

1. **穷举所有切分点取最优**（段落数是个位数，代价可忽略）
2. 目标函数 = 各栏字数偏离目标值的**平方和** + 栏内段落数偏差 × 400
3. **最优解仍不均衡（差 > 35%）就整段退回单栏**

第 3 条是关键：3 段 73/147/69 无论在哪个段间切，最好也只有 218 vs 74（差 66%）。
**这种情况下单栏才是对的**：左边一栏通到底、右边空着，远好过两栏一高一矮。
即「排版由内容决定，而不是强行套版式」。

**50 条真实数据实测：36 条双栏 / 14 条单栏**，退回的都是段落少或长度悬殊的。
thealgorithms 从 63% 不均降到 10%，markitdown 5%，anydoc 8%。

### 顺手修掉的内容缺陷：17 条正文有裸 Markdown

`body` 在数据层是**纯文本**（`tests/seed.test.mjs` 明确禁止 `##` 标题），
但 17 个条目按写作习惯写了 `**强调**` 和反引号，页面上**原样吐出星号**。

新增 `lib/inlineText.ts` + `components/RichText.tsx`：
- 只实现 `**粗体**` 与 `` `行内代码` `` 两种
- **不上完整 Markdown 渲染器**：那等于把 body 变成受信任 HTML 的入口
- 不用 `dangerouslySetInnerHTML`，内容全作为 React 文本节点输出
- 落单的标记原样保留，不吞后文（作者写错一个星号不能把正文吃掉）
- 标记不跨行匹配（跨行的 `**` 会把整段卷进strong）

### 测试：137 → 156 项

新增 `tests/body-columns.test.mjs`（9 项）与 `tests/rich-text.test.mjs`（10 项）。

**测试跑不了 `.tsx`**：`node --test` 不做 JSX 转译，
直接 import 组件报 `ERR_UNKNOWN_FILE_EXTENSION`。
所以把解析逻辑抽到 `lib/inlineText.ts`（纯TS，可测），组件只做渲染。
项目现有的 `GuideSection` 等组件都没有单测，同一原因。

两条断言的方向相反，都必须留：
- 一旦返回双栏就必须真的平（差 ≤ 35%）
- **判据不能过严到把内容全退回单栏**（`two >= 10`）——否则功能等于没生效

### 踩坑三：量测工具本身骗了我三次

布局类改动光看代码判断不了观感，必须实际渲染 + 精确量尺寸。
但**量测工具出错的概率和被测代码一样高**：

1. **「每栏 289px / 19 个汉字」**——量测脚本对多栏容器又除了一次栏数。
   多栏里段落的 `getBoundingClientRect` **已经是单栏宽度**。
   差点据此否掉一个其实没问题的方案。真实值是 426px / 28 字。
2. **「shell 仍是 1200px」**——量到的是页头的 `shell`，不是详情页的 `shell-wide`。
3. **「移动端横向溢出」**——`--window-size=390` 但 `clientWidth=497`，
   无头Chrome 按 390 裁图把内容切掉。实际 `scrollWidth === clientWidth`，
   22 个"溢出"元素全在 `overflow-x-auto` 容器内（表格的正常横向滚动）。
   **页面没问题，是截图工具的假象。**

教训：每次得出"有问题"的结论前，先量一遍**参照物**——
用 `Emulation.setDeviceMetricsOverride` 之外的手段确认视口真的是我设的那个。
另外 `Emulation.setDeviceMetricsOverride` **不要在 `Page.navigate` 之前调用**，
后续导航会重置渲染视口，而脚本还按原值算，量出来的是错的数。

###其它坑

- **选择器里类名含方括号**：`[class*="max-w-[52em]"]` 的方括号被当属性选择器语法，
  `querySelector` 抛错后错误以「序列化 HTMLDivElement 循环引用」的形式
  在很远的地方爆出来，完全看不出是选择器写错。
- **`indexOf('body:')` 命中 `somebody:`**这类子串——多个条目指向同一处正文。
  必须用行首锚定的正则。
- **种子里 `body` 里的换行是字面的 `\n` 两字符**，解析时要先还原成真换行再 split，
  否则 50 条全被误判成"1 段不分栏"。
- **`source[i]++` 写在 `buf += source[i]` 后面会死循环**——表达式取值后再自增，
  但这里 `i` 已在同一表达式里被求值两次，OOM。临时脚本改用文件避免转义地狱。
- **单栏时也要有行宽上限**：分栏退回单栏后 900px 视口下行宽达 54 字，
  加 `max-w-[42em]`（约 42 汉字）。
