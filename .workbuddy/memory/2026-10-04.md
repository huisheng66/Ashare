## 外链巡检脚本 stale-links（bunny 分支，接续 10-03 的回填）

- 新增 `lib/stale.ts`（纯函数：checkFreshness / staleItems / summarize / today）+ `scripts/stale-links.mjs`（`npm run stale-links`）。
- 用法：默认列过期条目；`--check` 探活、`--update` 回写、`--days N` 改阈值、`--all`、`--json`、`--strict`（CI）。抓取复用 `_shared.mjs` 的 safeFetch。
- **核心安全约束：只回写「全部链接都可达」的条目。** 实测两种场景都正确拒绝回写：单链接全失效、一个正常+一个失效（部分可达）。理由：把失效链接的日期刷成今天，下一轮会以为它刚查过，**死链被永久掩盖**，比过期本身更危险。`--update` 单独使用会被拒绝（没探活就刷日期等于伪造核验记录）。
- **`--update` 后必须同步种子**（linksCheckedAt 也在 SeedSoftware 里），脚本会提示。回写时同步 SHA-256 旁车。

**两个易错点**
1. **缺字段 ≠ 新鲜。** 把 undefined 当「没过期」的话，从未核验的条目永远不进报告 —— 而它们最该核。四种原因分开：已过期/从未核验/格式非法/新鲜。
2. **`2026-13-45` 形状对但日期不存在，正则查不出。** `Date.UTC` 会进位成 2027-02-14，算出负天数被当成「未来→新鲜」。必须回读校验年月日（isRealDate）。2026-02-29 非法、2024-02-29 合法。已写测试覆盖。

**其他**
- `LINK_KEYS` 在 lib/stale.ts 与 lib/links.ts 各一份（前者是 `as const` 数组，无法 import type 值——注意这与 click-analytics 的情况不同，那里能 import type 是因为只用作类型标注）。
- 测试 78 → 90（新增 12）。实机验证：三种过期情形检出、探活回写 3 条、两种失败场景均不回写、运行库还原且 SHA 匹配。build 通过（10-03 那轮被环境 SIGTERM 中断的构建，本轮一并通过）。

### 追加：外链巡检接入 CI

- 新增 `.github/workflows/link-watch.yml`：每天 04:17（避开整点拥堵）+ 手动触发 + 改链接相关文件即触发。报告用 `tee` 一次产出，失败时 `if: always()` 仍上传工件。**不跑 npm ci**（只用 node: 内置模块）。
- `--source seed`：`data/store/` 已 gitignore，CI 上只有种子。此模式禁止回写。
- **`--check-all` 才是 CI 该用的**：链接昨天还正常、今天挂了，只查「过期」发现不了。门槛决定「何时必须复验」，不限制「能查什么」。
- **`--flaky-ok`**：误报豁免（仅 `--strict` 下有意义）。没有它 CI 会天天红，人会习惯性忽略，真死链被淹没。

**三个 bug（都是实跑才暴露的）**
1. `github.com` 网页端在 CI 全超时（网络策略）。`check-links` 早有 API 代验能力但我没复用 —— 已把 `githubApiOf` 抽到 `_shared.mjs` 两者共用。异常 7 → 1。
2. **`--source seed` 漏掉半数条目**。种子是 SeedSoftware 形态（官网在 `officialUrl` 而非 `links.official`），30 条只有 18 条填了 `links` → 直接读种子只探活 34 个链接（运行库 51 个），「全站巡检」名不副实且报告一切正常。**必须先过 `seedToItem()`**，已加测试断言转换后 51 = 运行库 51。
3. 参数校验顺序：`--strict` 的「需要 --check」写在 `--check-all` 联动 `args.check` 之前，把合法组合判成非法。**参数校验顺序本身就是逻辑**。

**最终实跑**：51 个链接、3 个异常全是已知误报、全部豁免、**退出码 0**。测试 90 → 93。
