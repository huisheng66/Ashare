# 教程价值审计

> `node --input-type=module scripts/audit-guides.mjs` 生成。
> 判定立场：教程的价值是「替用户踩过坑」，不是「复述官方 README」。
>
> 第一版按小节标题分类，353 节里 311 节落进「待定」—— 等于没审。
> 真实标题长相出乎意料（`git add . 到底加了什么`、`独立附件是个坑` 看着像操作，
> 实际是实战经验），所以改为读正文找信号。

**55** 篇教程、**353** 个小节。

| 判定 | 小节数 | 占比 |
| --- | --- | --- |
| 留 | 194 | 55% |
| 待定 | 11 | 3% |
| 复述 | 7 | 2% |
| 中性 | 141 | 40% |

## 信号覆盖

一个小节可命中多个信号。

| 信号 | 小节数 | 占比 | 官方文档是否提供 |
| --- | --- | --- | --- |
| 坑（失效现象与原因） | 97 | 27% | 不提供 |
| 取舍（何时别用） | 38 | 11% | 不提供（利益冲突） |
| 比较（横向对比） | 38 | 11% | 不提供 |
| 后果（说后果而非说坑） | 129 | 37% | 不提供 |

## 结论

**1. 没有一篇教程是多余的。** 判为「复述」的仅 7 节（2%），
且每节都同时带有实战信号 —— 没有任何一节是纯粹的官方介绍复述。

**2. 官方文档结构性缺失的三块，我们覆盖得不错：**

| 缺什么 | 官方为什么不写 | 我们的覆盖 |
| --- | --- | --- |
| 何时别用 | 厂商不会劝退自己的产品 | 38 节 |
| 排错与踩坑 | 只在真实使用里暴露 | 97 节 |
| 横向对比 | 单项目 README 只讲自己 | 38 节 |

**3. 但这个方法有天花板，「中性」141 节（40%）不能直接删。**

判定从 39% 迭代到 55%，靠的是不断补充词表。但抽样核对后发现，
剩下的「中性」里仍有大量高价值内容，只是表达更含蓄：

> `混用 Tab 和空格会直接报 IndentationError`（python · 缩进就是语法）
> `循环引用时后加载的一方拿到的会是尚未填充完毕的 exports`（nodejs · 循环依赖）
> `免费额度对纯文本条目够用，攒 PDF 就会超`（zotero · 存储空间）
>
> 这些节既不说「坑」也不说「别用」，而是**陈述后果**或**给场景对照表**。
> 关键词匹配识别不出这种写法 —— 这是方法本身的局限，不是内容的问题。

**结论：这份报告能确认「教程有独立价值」，但不足以支撑「删掉哪些」。**
若要逐节判定，仍需人工阅读。可以确定要处理的只有下面两类。

## 一、可确认要处理的篇目

### 1.1 疑似「复述」小节（7 篇，低置信度）

这些小节命中了「概念定义/官方定位」信号且实战信号为零，**但抽样核对后多数仍属误判**。
例如 Jupyter 的「公式与输出的渲染」实际讲的是中文与 LaTeX 混排的字距问题、
Windows 控制台输出乱码该怎么加两行 Python—— 官方文档不会写这些，
只是正文里恰好出现了一次「见官方文档」而被判复述。

**结论：这 7 节都需要人工确认后再决定，不建议据此删除。** 真正需要处理的只有 1.2 那一篇。

- **Jupyter**（`jupyter`）—— 公式与输出的渲染
- **TUIOS**（`tuios`）—— 平铺不是叠放
- **VoiceStudio**（`voicestudio`）—— 接入你的智能体
- **Effect**（`effect`）—— 上手顺序
- **yoinks**（`yoinks`）—— 合理使用
- **Stremio Web**（`stremio-web`）—— 生态：它最强的地方
- **The Algorithms (Python)**（`thealgorithms`）—— 读一份实现时留意 doctest

### 1.2 零实战信号的篇目

**无。** 唯一被判零信号的 yoinks 经人工阅读确认是误判 ——
它的「现在还不能做的」列了 5 条未实现的 roadmap 项，「评估供应链时要知道」
提醒首次运行会下载并执行第三方二进制，两节都是官方 README 不会写的内容。
已排除在清单外（脚本里留了排除原因）。

**也就是说：没有一篇教程可以判定为「该删」。**
