## 一、防盗链（`lib/hotlink.ts`）

### 问题

`app/media/[...path]/route.ts:18` 与 `app/icons/[slug]/route.ts:14` 对所有来源照常返回图片。任意站点可用 `<img src="https://ashare…/media/vscode/xxx.png">` 拉走预览图，消耗带宽与磁盘。

### 核心设计：白名单放行 + 其余拒绝

方向的选择是这一层最关键的判断。站内图片数量有限、**防得住**；爬虫与分享流量不可枚举、**拉黑就等于把索引和分享一起废掉**。因此判定写成放行四类（`lib/hotlink.ts:67-85`）：

| 放行 | 行号 | 理由 |
|---|---|---|
| 无 Referer | `lib/hotlink.ts:74` | 地址栏直开、分享、部分 App 内置浏览器、爬虫抓 og:image |
| 同站及子域名 | `lib/hotlink.ts:77` | 首屏与 `next/image` 优化器回源 |
| 显式白名单 | `lib/hotlink.ts:81` | `ASSET_REFERRER_ALLOWLIST` |
| 关闭开关 | `lib/hotlink.ts:71` | `ASSET_HOTLINK_PROTECTION=0` |

### 三个容易写错的点

**1. 后缀伪装必须拦下（`lib/hotlink.ts:48-50`）**

```ts
function hostMatches(host: string, own: string): boolean {
  return host === own || host.endsWith(`.${own}`);
}
```

`evilashare.example` 与 `ashare.example.evil.com` 都会被此判定拦下 —— 只做 `===` 会漏前者，只做 `endsWith` 会漏后者。测试见 `tests/hotlink.test.mjs:25`。

**2. 拒绝响应必须 `no-store`（`lib/hotlink.ts:134-143`）**

```ts
status: 403,                                   // :136
"Cache-Control": "no-store",                  // :139
"X-Robots-Tag": "noindex",                    // :140
"Cross-Origin-Resource-Policy": "same-origin" // :141
```

图片路由原本是 `immutable` 一年缓存（`app/media/[...path]/route.ts:36`）。403 若沿用该缓存头，浏览器与中间代理会把拒绝结果缓存住，改配置后仍不放行。返回 403 而非 404 是有意的：文件确实存在，假装不存在只让排障变难。

**3. 判定放在读盘之前（`app/media/[...path]/route.ts:25-29`）**

```ts
if (!decideHotlink(request.headers.get("referer"), hotlinkOptionsFromEnv()).allowed) {
  return hotlinkBlockedResponse();
}
```

被拒请求不消耗磁盘 IO，也不进 ETag 计算。

### 双层防护

Referer 会被浏览器策略裁剪，因此 `next.config.ts:28` 补 `Cross-Origin-Resource-Policy: same-origin` 作为浏览器侧兜底；`next.config.ts:30` 补 `X-Robots-Tag: noindex` 防止预览图被单独索引。

### 接入点

| 文件 | 行号 | 内容 |
|---|---|---|
| `app/media/[...path]/route.ts` | 4-8, 19-25, 30 | import、判定、响应头 |
| `app/icons/[slug]/route.ts` | 4-8, 17-23, 33 | 同上 |
| `next.config.ts` | 21, 28, 30 | CORP + noindex |
| `.env.example` | — | 两个新环境变量 |

## 二、外链规范化（`lib/links.ts` + `components/OutboundLink.tsx`）

### 问题

`links` 用命名槽位（`official` / `homepage` / `github` / `disk`）表达渠道，这四个字段在「主 CTA」「渠道列表」「镜像说明」三处各自判断了一遍。新增一种渠道要改三处。

### 解决：读取侧摊平，存储结构不变

`lib/links.ts:67-84` 把槽位摊平成有序 `LinkChannel[]`。**存储结构不动，35 条存量数据零迁移** —— 这是刻意的取舍：数据迁移的风险远大于读侧多一次转换。

```ts
const CHANNEL_SPECS = [                                        // :44
  { id: "official", role: "primary", label: "官网" },
  { id: "homepage", role: "product", label: "产品主页" },
  { id: "github",   role: "repo",    label: "GitHub" },
  { id: "disk",     role: "mirror",  label: "已核验镜像" },
];
```

### 主 CTA 永不选镜像（`lib/links.ts:90-96`）

```ts
export function primaryChannel(links: ItemLinksData): LinkChannel | undefined {
  return channels.find((c) => c.role === "primary")
    ?? channels.find((c) => c.role === "repo")
    ?? channels.find((c) => c.role === "product");   // 没有 mirror 分支
}
```

只有镜像时返回 `undefined`（而不是退回镜像）—— 镜像退化成「网盘分发」，不能当主入口。测试 `tests/data-model.test.mjs:21`。

### 无说明的镜像不展示（`lib/links.ts:103-105`）

```ts
export function isVerifiedMirror(channel: LinkChannel): boolean {
  return channel.role !== "mirror" || Boolean(channel.note?.trim());
}
```

无法核验的镜像与盗版网盘只有一线之隔。`components/ItemLinks.tsx:18` 据此过滤，空白说明等同没有说明（`tests/data-model.test.mjs:31`）。

### 统一出站链接（`components/OutboundLink.tsx`，124 行）

收口三件以前散在各处的事：

| 事项 | 位置 | 说明 |
|---|---|---|
| `target`/`rel` | `:79`（cta）/ `:97`（row） | 一律新标签 + `noopener noreferrer`，主 CTA 另加 `nofollow sponsored` |
| 域名可见 | `:110-112` | 等宽字体，镜像额外加「镜像」角标 `:105-107` |
| 点击上报 | `:34-44` | `mousedown` 而非 `click` —— 按住拖走也会触发跳转 |

读屏提示区分镜像（`:117`）：普通渠道「在新标签页打开」，镜像「第三方镜像域名，非官方，请核对」。

## 三、点击统计闭环（`lib/click-store.ts` + `lib/click-analytics.ts`）

### 为什么不用 `JsonStore`

`lib/json-store.ts` 的读改写事务会让每次点击都串行等锁。点击是高频、低价值、允许极小概率丢失的事件 —— 因此用 JSONL 追加写，`lib/click-store.ts:41-56`。一次 `appendFile` 即持久化。

### 隐私决策（`lib/click-store.ts:11-12`）

```ts
 * - **只存 slug + 渠道 +时间**，不存 IP、不存 UA。定位到具体条目的点击已经够用，
 *   存 IP 会把这份数据变成第二份用户数据，隐私成本远高于收益。
```

### 读侧：只扫尾部

`lib/click-store.ts:153-200` 的 `scanClicks()` 只读文件**尾部 8 MiB**（`MAX_SCAN_BYTES`，`:99`）与 20 万行（`MAX_SCAN_LINES`，`:100`）。JSONL 每天只追加、永不压缩，理论上无上限 —— 后台画一张图不该把全部历史读进内存。

超限时在页面上如实说明跳过多少条（`app/admin/clicks/page.tsx:130-135`），**不把部分数据说成全量**。

### 一处易错：截断的首行（`lib/click-store.ts:157`、`:170-175`）

```ts
if (firstPartial) {
  firstPartial = false;
  if (!trimmed.startsWith("{")) continue;   // 半条 JSON，跳过
}
```

从尾部截断时首行可能只有半条记录。若不单独标记，它会被误记成「损坏行」，让统计看起来像在丢数据。

### 展示层聚合（`lib/click-analytics.ts`，158 行）

原始数据是 `(slug, channel, time)` 三元组，直接渲染会得到一堆重复条目的行。`itemClickRows()`（`:68`）折成「每条目一行 + 渠道拆分」。

三条关键行为：

| 行为 | 行号 | 理由 |
|---|---|---|
| 已删除条目保留历史 | `:96-99` | 删条目不该让点击历史凭空消失；顺便提示该清理 slug |
| 白名单外渠道丢弃 | `:88-90` | 只接受 4 个 id，别的只可能是脏数据或旧版本残留 |
| 占比以总量为分母 | `:101-106` | 各行之和恒为 1（`tests/click-analytics.test.mjs:49`） |

趋势图**补齐没有点击的日期**（`lib/click-analytics.ts:133-152`）—— 直接跳过空日期会让连续 7 天看起来只有 3 天。测试 `tests/click-analytics.test.mjs:121`。

### 页面（`app/admin/clicks/page.tsx`）

纯 CSS 画柱状图，未引入图表库（后台一个页面不值得加 200KB 依赖）。四板块：总体指标 / 14 天趋势 / 渠道构成 / 条目明细。空状态按 `EmptyState` 规范给出下一步并说明数据文件位置（`:72-84`）。

### 接入点

| 文件 | 行号 | 内容 |
|---|---|---|
| `app/track/actions.ts` | 1-25 | Server Action，白名单 + 限速 60 次/分钟 |
| `components/AdminTabs.tsx` | 9 | 第三个分段标签 |

### 一处工具链冲突

`lib/click-analytics.ts` 需要运行时的 `isChannelId`（值，不能被类型擦除）。但测试靠 `node --test` 直接跑 `.ts`，相对导入必须带 `.ts` 扩展名；而 tsconfig 未开 `allowImportingTsExtensions`，带扩展名会让 `tsc` 报 TS5097。**两边无法同时满足**，只能让白名单就地定义（`lib/click-analytics.ts:4-18`），同步由 `tests/click-analytics.test.mjs:11` 守住。

## 四、数据范式（`lib/semantics.ts` + `lib/derive.ts`）

### `source` 与 `kind` 的矛盾根治

此前两者独立填写、前台徽章只认 `source`，于是出现 GeoGebra 那类错误：种子标 `source: "opensource"` → 被 `seedToItem` 推导成 `kind: "opensource"` → 前台挂「开源」徽章，但它仓库 `license` 为 null（源码公开、许可闭源），实为非商业免费。

写成矩阵（`lib/semantics.ts:16-20`）：

```ts
const SOURCE_KIND_MATRIX: Record<SourceKind, Partial<Record<ItemKind, string>>> = {
  official:   { app: "厂商正式版应用", script: "官方分发的脚本工具" },
  opensource: { opensource: "开源项目", app: "开源但以应用形态分发的工具" },
  discount:   { app: "官方优惠的正式版应用" },
};
```

后台 `saveItem`（`app/admin/actions.ts:201-203`）与 `ingest` 脚本共用同一份定义，从人肉判断改为机器拦截。

**这套规则在本次回填时抓到一处真实数据错误**：`yt-dlp` 标 `opensource` + `script` 组合不合法，已改为 `opensource`（Unlicense 公开领域，「脚本」只是形态描述）。

### 语义层只管跨字段一致性

`lib/semantics.ts:61-82` 不校验「至少一个场景/平台」这类单字段必填 —— 那些由 `saveItem` 与 ingest 各自的既有校验负责。**这是本轮唯一回归的成因**：最初包含单字段必填，导致 `tests/admin-actions.test.mjs` 两个子测试失败。重复校验会让同一问题在两处以不同措辞报错。

### 图标回退收进纯函数（`lib/derive.ts:17-34`）

三套图标机制（`iconImage` 上传图 / `icon.simpleIcon` 本地 svg / `icon.letter` 字母块）的回退顺序此前内嵌在 `components/SoftwareIcon.tsx` 里，抽成 `resolveIcon()` 后可被 ingest 与测试复用。`/icons/` 下的 svg 标 `optimize: false`（`lib/derive.ts:24`）—— 走 `next/image` 优化器收益小且要多解码一次。

### `scenes[0]` 主场景约定显式化（`lib/derive.ts:42-44`）

此前只散落在审计脚本注释与批量归属规则里，任何新增代码都得重新确认一遍。

## 六、巡检与 CI

### `lib/stale.ts`（151 行）

**缺字段 ≠ 新鲜**（`lib/stale.ts:93`）—— 这是最容易写错的地方。若把 `undefined` 当「没过期」，从未核验的条目永远不进报告，而它们最该核。四种原因分开：已过期 / 从未核验 / 日期格式非法 / 新鲜。

**日期合法性要回读校验**（`lib/stale.ts:24-30`）：

```ts
function isRealDate(value: string): boolean {
  const date = new Date(Date.UTC(y, m - 1, d));
  return date.getUTCFullYear() === y && date.getUTCMonth() === m - 1 && date.getUTCDate() === d;
}
```

只过正则 `^\d{4}-\d{2}-\d{2}$` 不够 —— `2026-13-45` 形状对但日期不存在，`Date.UTC` 会进位成 2027-02-14，算出负数天数后被当成「未来 → 新鲜」。测试 `tests/stale.test.mjs:32`。

### `scripts/stale-links.mjs`（295 行）

**核心安全约束：只回写「全部链接都可达」的条目**（`:245`）

```ts
if (list.every((r) => r.ok)) fullyOk.add(slug);
```

实测两种情况均正确拒绝回写：

- 单链接全失效 → 「没有全部可达的条目，核验日期未改动」
- 一个正常 + 一个失效（部分可达）→ 同样不回写

理由：把失效链接的日期刷成今天，下一轮会以为它刚查过，**死链被永久掩盖** —— 比过期本身更危险。

`--update` 必须配合 `--check`（`:63`），否则拒绝执行：没探活就刷新日期等于伪造核验记录。

## 八、过程中发现并修掉的自身缺陷（重要）

这一节记录的不是功能，是**我在实现过程中犯的错**。它们已被写入 `.workbuddy/skills/ashare-curation/references/known-pitfalls.md`（第 54–73 条）。

### 8.1 语义层越界（1 个回归）

`validateSemantics` 最初包含「至少一个场景 / 平台」，导致 `tests/admin-actions.test.mjs` 两个子测试失败。用 `git stash` 对比确认是本轮引入而非环境问题后，定位到根因：那些测试构造的 FormData 本就不带 `scenes`。

**结论**：单字段必填归各入口校验，语义层只管跨字段一致性。

### 8.2 空字符串 ≠ 缺省

草稿里给无版本号的条目写了 `version: ""`，运行库存 `""`、种子是 `undefined` → `seed-drift` 报 6 处不一致。清理 6 处并同步 SHA-256。

### 8.3 仓库文件是 CRLF

补种子时脚本**连续三次静默地什么都没做**，一度以为已同步完成。三个叠加原因：

1. shell 把 `node -e` 里正则的 `$` 吞成字面量
2. 用「已处理输出」判重会误判
3. **`$` 前留着 `\r`**，导致 `slug: "x",$` 永远不匹配

解法：写 `.mjs` 脚本文件而非 `node -e`；按条目切片而非逐行判重；读入时 `.replace(/\r\n/g,"\n")`、写回时恢复原行尾（否则 diff 变全文件）。

### 8.4 空字符串绕过日期校验

测试直接抓到：`""` 不匹配 `undefined` 分支，被判为 `invalid` —— 但 `saveItem` 的 `"" || undefined` 会把它变成缺省。两种语义必须分开。

### 8.5 CI 上 `github.com` 全部超时

首跑 7 个异常里 6 个是它。`check-links.mjs` 早有「用 `api.github.com` 代验」的能力，但新脚本没复用。抽出 `githubApiOf` 到 `_shared.mjs` 后，异常 7 → 1。

### 8.6 `--source seed` 漏掉半数条目

探活数出 34 个链接，运行库有 51 个。根因：**种子是 `SeedSoftware` 形态**，官网在 `officialUrl` 而非 `links.official`，30 条里只有 18 条填了 `links`。直接读种子，那 17 条被静默漏掉，**而报告仍显示一切正常**。

必须先过 `seedToItem()`（`scripts/stale-links.mjs:90-105`），转换后 51 = 51。已加测试 `tests/stale.test.mjs:137`。

### 8.7 参数校验顺序本身就是逻辑

`--strict` 的「需要配合 `--check」校验写在 `--check-all` 联动 `args.check` 之前，于是 `--check-all --strict` 这个合法组合被判成非法、退出码 1。已调整为先联动再校验（`scripts/stale-links.mjs:60-68`）。

### 8.8 造测试数据改错字段（拿到假绿灯）

注入死链后 CI 报 `success`。查下来是我改了 `officialUrl`，而 `seedToItem` 里 `links` 优先 —— 死链压根没被探到。

**教训：绿灯必须逐项核对数字（探了几个、异常几个），否则「没报错」和「没检查」分不清。**

### 8.9 防盗链在本地开发时全站 403（最严重的一处）

启动应用做实机验证时才发现：curl 带同站 Referer 请求图标，**返回 403**。

根因是 `hotlinkOptionsFromEnv()` 只读 `NEXT_PUBLIC_SITE_URL`（`lib/hotlink.ts:89`），而 `.env.local` 里没配这个变量 —— `siteHost` 为空，`decideHotlink` 的同站判断直接失效（`lib/hotlink.ts:77`）。**结果本地开发时首屏所有图标都是 403。**

为什么前几轮没发现：那轮我是在 `SESSION_SECRET=... npm run start` 下手工构造了 `NEXT_PUBLIC_SITE_URL` 才做的六项验证，而**真实开发流程是 `npm run dev` + `.env.local`**。验的环境不是实际使用的环境，等于没验。

修法：新增 `requestHost()`（`lib/hotlink.ts:119-131`），拿请求自身的 host 作兜底 —— 「谁在访问我」本来不需要任何配置。两个路由改为「配置缺失时用 requestHost 补上」（`app/icons/[slug]/route.ts:17-19`、`app/media/[...path]/route.ts:25-26`）。

`x-forwarded-host` 只在 `TRUST_PROXY=1` 时采纳，与 `lib/guard.ts` 对 XFF 的既有约定一致。这一点在本场景不是安全关键（伪造它最多让伪造值等于 own，而真正的跨站请求其 referer 域不会因此变成 own），仍按约定收紧以免与文档不符。

**教训：验证环境必须等于使用环境。** 手工构造一串环境变量跑生产模式，不等于「开发者明天会怎么跑」。
